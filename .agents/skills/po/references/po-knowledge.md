## PO Foundation — Vai Trò & Trách Nhiệm

### PO Là Ai, Không Là Ai
```
PO LÀ:
✅ Người chịu trách nhiệm về VALUE (Outcome Owner)
✅ Người quyết định "Build cái gì" và "KHÔNG build cái gì"
✅ Người bridge giữa Business, UX, và Technology
✅ Voice of the Customer trong team
✅ Analyst: phân tích vấn đề trước khi giải (POA mindset)

PO KHÔNG LÀ:
❌ Project Manager (không quản lý timeline/resource)
❌ Business Analyst (không chỉ ghi nhận yêu cầu — PO validate need)
❌ Scrum Master (không facilitate ceremonies)
❌ Feature Factory Manager (không phải "nhận order → giao hàng")
```

### Ba Loại PO Role
```
1. Discovery PO (Exploration): Tìm problem đúng, validate solution concept
2. Delivery PO (Execution): Ship đúng, ship nhanh, ship chất lượng
3. Growth PO (Optimization): Tối ưu metrics, retention, revenue
```

### Product vs Project
```
PRODUCT thinking:                    PROJECT thinking:
- Continuous evolution               - Has start/end date
- Measured by outcome                - Measured by on-time/on-budget
- Backlog lives forever              - Scope fixed upfront
- "Are we building the right thing?" - "Are we building the thing right?"
```

## POA Mindset — 7 Domains Summary

### D1: Apply Foundational Concepts
```
Mindset: "Hiểu context trước khi hành động."
- PO type phù hợp? (Discovery/Delivery/Growth)
- Product lifecycle stage? (Introduction/Growth/Maturity/Decline)
- Tổ chức ready cho product-centric approach chưa?
```

### D2: Cultivate Customer Intimacy
```
Mindset: "Thấu hiểu customer hơn cả họ tự hiểu mình."
- Empathy trước, solution sau
- Interview ≥ 5 real users trước khi commit feature
- Value Proposition phải map được: customer pains ↔ product relief
```

### D3: Engage the Whole Team
```
Mindset: "Product success = team responsibility, không phải PO alone."
- Three Amigos trước mỗi sprint
- Discovery track chạy song song Delivery track
- Collaborative games > HiPPO meetings
```

### D4: Make an Impact
```
Mindset: "Mỗi feature là 1 investment — phải có ROI."
- OKR drive roadmap, không phải feature requests
- Impact Map trace feature → business goal
- Business Case justify trước, build sau
```

### D5: Deliver Often
```
Mindset: "Deliver thin slices, not thick layers."
- Story Map → release walking skeleton trước
- Job Stories khi context quan trọng hơn role
- DoR → DoV → DoD: 3 gates, không skip
```

### D6: Learn Fast
```
Mindset: "Test assumptions cheap, fail fast, learn faster."
- MVP = test hypothesis, không phải mini product
- Real Options: delay decisions until last responsible moment
- Learning Loops formalize: Daily → Sprint → Release
```

### D7: Obsess About Value
```
Mindset: "Maximize value created, minimize waste produced."
- RICE/WSJF/Kano cho prioritization
- Value Stream Mapping cho delivery efficiency
- Sunset features nobody uses
```

## Problem Validation (5 câu PHẢI hỏi)
```
1. "Vấn đề này ảnh hưởng bao nhiêu user? Tần suất?"
2. "User hiện đang giải quyết bằng cách nào? (Workaround)"
3. "Nếu giải quyết được, metric nào cải thiện?"
4. "Tại sao bây giờ? Priority so với các issue khác?"
5. "Stakeholder có data nào support không?"
```

## Opportunity Assessment (Marty Cagan)
```
1. Vấn đề chính xác là gì?
2. Cho ai? (Persona cụ thể)
3. Thành công trông như thế nào? (Metrics SMART)
4. Core business? (Make vs Buy vs Partner)
5. Tại sao chúng ta capable?
6. Tại sao bây giờ?
```

## Metrics Principles
```
1. Vanity (Total signups, Page views) ≠ Actionable (Retention, NPS, LTV)
2. Mỗi feature ship phải gắn với ít nhất 1 actionable metric
3. Không track metric mà không có kế hoạch hành động khi nó thay đổi
```

## Stakeholder Mindset
```
1. PO không tránh conflict — PO resolve conflict bằng data và transparency
2. Mọi quyết định phải documented + accepted risk ghi rõ
3. "Nói NO" là kỹ năng, không phải thái độ — luôn kèm data + alternative
```
